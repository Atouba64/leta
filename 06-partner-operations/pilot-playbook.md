# Partner pilot playbook — first 5–10 tickets

**Goal:** Prove **no-call visibility** + **on-time GA fulfillment** without building every v2 integration.

## Week 0 — setup

- Complete [`onboarding-checklist.md`](./onboarding-checklist.md)
- Pick pilot **anchor** from [`../data/georgia-coverage.json`](../data/georgia-coverage.json) (e.g. Macon + Savannah, or ATL + Columbus) — see [`georgia-dispatch-corridors.md`](./georgia-dispatch-corridors.md)
- Name partner dispatcher + Leta ops owner

## Week 1 — tickets 1–3

| # | Type | Success signal |
|---|------|----------------|
| 1 | Simple break/fix (low risk) | Timeline accurate; partner didn’t call |
| 2 | POC-only site | Tech respected contact policy |
| 3 | Skill gap ticket | Leta Live used OR resolved first visit |

**Daily:** 10-min sync — open risks, SLA clocks.

## Week 2 — tickets 4–10

- Introduce hourly + flat mix
- Test cancel-on-arrival rule once (tabletop)
- Export first **billing CSV**

## KPIs (report in QBR deck)

| Metric | Target (pilot) |
|--------|----------------|
| Status calls from partner | <1 per 5 WOs |
| First-time fix | ≥80% |
| On-time arrival | ≥90% |
| Tech payout | ≤48h |
| Dispute rate | <5% |

## Graduate to production when

- [ ] 10 WOs without SLA breach attributable to Leta dispatch
- [ ] Partner AP accepts CSV format
- [ ] Signed production MSA or pilot extension

## Fail pivot

If partner insists on phone-only dispatch → **coopetition off-ramp** or limited “human dispatch” tier with higher fee.
