# Customer portal — user stories (Leta)

Audience: **B2B and B2C** customers who need IT break/fix without phone-tag.

## Epic: Request and understand the job

- **As a customer**, I want to **submit a service request** with location, device type, and problem description so that Leta can route the right technician.  
- **As a customer**, I want to see an **estimated cost range** (from rate card or partner rules) before I confirm dispatch so that I can decide whether to proceed.  
- **As a customer**, I want to pick a **service window** (urgent vs scheduled) so that pricing and SLA expectations are clear.

## Epic: Visibility while waiting

- **As a customer**, I want **live status** (assigned → en route → arrived → in progress) so that I am not guessing when help will show up.  
- **As a customer**, I want **map-based tracking** of my assigned field tech (Georgia rollout) similar to consumer delivery apps, **within privacy and safety constraints**.  
- **As a customer**, I want **notifications** (SMS/email/push) for key state changes so that I do not have to keep the app open.

## Epic: Service delivery and proof

- **As a customer**, I want to **approve scope changes** if the technician discovers additional work so that I control cost creep.  
- **As a customer**, I want a **digital signature** and **summary receipt** at completion so that I have records for expenses or warranty.  
- **As a customer**, I want to **rate the experience** and flag issues so that Leta can improve quality.

## Epic: Payments and support

- **As a customer**, I want to **pay securely** in-app or via invoice (depending on segment) so that checkout matches my procurement process.  
- **As a customer**, I want a **support chat** tied to my ticket so that disputes are contextual.

## Non-goals (initial)

- Deep RMM remote control of customer devices (may integrate later via partner tools).  
- Unbounded “free triage” that burns technician time without dispatch rules.
